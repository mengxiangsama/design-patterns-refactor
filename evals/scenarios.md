# Skill 行为评估场景

这里是评估方法和评分依据，不是通过率报告。独立评估时只提供 Skill 目录、选定的 `tasks/` 请求和该请求列出的输入副本，**不要把本评分文件、预期方案或其他评估者结论传给代理**。使用临时工作区，先保存回答和 diff 再评分；不得修改仓库中的原始夹具。记录模型、日期、请求、输出、文件差异和实际运行命令。实例测试通过不等于模型评估通过。

| 场景 / 请求 | 应观察的行为 | 不应发生 |
| --- | --- | --- |
| 只分析 PricingCase.Before，说明何时值得策略，先别修改 | 识别规则族，比较稳定分支与可扩展策略，引用实际代码 | 未授权写文件，因存在 switch 直接定为缺陷 |
| 改造物流 SDK 接入，保持现有错误和单位契约 | Adapter，千克转克不丢精度，供应商失败和调用次数保持 | 自动重试发货、将失败转成成功或空字符串 |
| 扩展导出压缩与编码组合 | Decorator，说明顺序影响，四种旧组合等价测试 | 只有接口没有实现，解码顺序错误 |
| 两个稳定条件分支值得套设计模式吗 | 允许保留直接实现，说明扩展收益不足 | 强制产生多个类 |
| 这是订单测试 Demo，生产代码另查数据库 | 按 Demo 定位评价，给出真实接入条件 | 将内存缓存一律写成生产高危漏洞 |
| [Python 只读分析](tasks/python-analysis.md) | 引用具体数据流，稳定分支允许直接实现，无文件差异 | 用类层次替代两个稳定分支，套用 Java 框架，未经请求写文件 |
| [Python 方法内清理](tasks/python-cleanup.md) | 删除确认为无用的绑定/覆盖赋值，保留审计调用一次、异常顺序、金额与未知会员回退；原契约测试通过 | 删除审计副作用、改变求值顺序、浮点替代 Decimal、修改测试掩盖回归 |
| [订单与消费可靠性](tasks/delivery.md) | 识别业务提交后丢事件、业务副作用与去重分开提交；比较本地持久化待办和原子去重，覆盖确认丢失与重启 | 仅加 try/catch 或 after-commit 就宣布可靠，进程内集合当持久化幂等，宣称生产验证通过 |
| [消息拓扑](tasks/topology.md) | 区分独立业务订阅和同职责实例竞争，按订单排序，提交后确认，重放保留去重语义，列出未知产品/保留期 | 四实例竞争导致业务遗漏，重放自动换 ID，无产品依据却给可直接部署的配置 |

## 本地基线

实际运行记录：[2026-09-28 三场景独立抽查](results/2026-09-28.md)。与下方夹具测试区分，不将抽查结果外推为通用通过率。

```bash
python3 -B -m unittest discover -s evals/fixtures/python_cleanup -v
python3 -B -m unittest discover -s evals/fixtures/order_delivery -v
```

订单夹具的 `test_baseline.py` **有意验证原实现会丢失投递机会/重复入账**，用于确认题目可复现，不是修复验收。若要求评估代理实施修复，应另建验收测试：业务与待发记录原子提交、重启后重试可恢复、投递成功后确认丢失可重投、去重与入账原子提交、重复投递只产生一次业务效果，并检验失败与并发路径。SQLite 本地试验不证明真实 MQ/生产数据库语义。

每项独立记录 `pass / partial / fail` 并引用输出或 diff；只读任务出现文件改动直接判失败。不要以是否出现特定模式名称或标题作为通过标准，也不把一次评估推广到所有模型、语言和项目。可执行案例与安装测试只证明各自覆盖的契约。
