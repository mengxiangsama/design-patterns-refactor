# Java / Spring 按需注意事项

- 读取真实 pom/Gradle 配置及 wrapper；Java 编译目标不代表当前运行 JDK。不要因为重构顺手升级 Boot、Jakarta 包名或全仓依赖。
- 注册器可用构造注入及实例级只读 Map。若“重复 key 覆盖”是历史可见行为，将启动失败的变化单独列出。只读 Map 不代表内部服务自动线程安全。
- 不能因为类名是 Factory/Handler/Abstract 就判定模式。模板方法要有稳定步骤骨架；Map<Integer, Consumer> 更接近动作分发。
- 若引用方法被事务/缓存/AOP 包装，检查自调用、private/final 方法、代理对象绑定以及事务传播。抽方法或改继承关系可能改变切面是否生效。
- 将状态机视为校验和转换工具时，每次用权威状态恢复后处理事件；数据库条件更新/版本号与事务必须防止读后写覆盖。进程内 synchronized 不能防多实例竞争。
- sendEvent 返回接受与否是否等同转换完成依赖版本和执行模型；核对同步/异步配置后再承诺 send-and-get 的行为。
- PAY 是业务事件，不是真实支付；不能从枚举名推断鉴权已完成。Demo 内存状态不是生产缺陷，用户的生产读取/持久化流程应基于实际代码评审。
- Observer 或事务事件监听器不自带可靠队列；after-commit 失败不会让已经提交的数据回滚。仅在需求需要时引入 Outbox。
- 包装第三方副作用时不要加无条件重试。核实操作幂等键、超时后查询路径及失败传播。
- 优先在原有测试框架验证分支、异常、金额/单位、顺序以及事务边界。构建失败应报告具体原因，不把 diff 检查当作运行验证。
