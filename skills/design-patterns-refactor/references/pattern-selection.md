# 模式选型：从变化点到最小抽象

先判断问题是否值得引入抽象，再选择类别。下表是候选集合，不是生成任务清单。

## 创建型（5）

| 模式 | 适用证据 | 不适用或代价 |
| --- | --- | --- |
| 工厂方法 Factory Method | 稳定的创建流程需要由扩展实现选择一个产品 | 单次 new 无变化点；简单函数/注册表可能足够 |
| 抽象工厂 Abstract Factory | 多个产品必须属于同一个兼容家族，例如同供应商客户端与认证器 | 仅有一个产品时过度设计；新增产品种类要改所有工厂 |
| 建造者 Builder | 分步构建、有可选字段且存在构建时约束 | 少量必填字段用构造函数；不要允许生成半合法对象 |
| 原型 Prototype | 由现有配置复制复杂对象并局部修改 | 可变子对象共享、浅拷贝泄漏；先定义复制语义 |
| 单例 Singleton | 明确需要进程内唯一且生命周期可控的实例 | 不代表集群唯一；优先沿用容器生命周期，避免隐藏依赖和可变全局状态 |

Spring Bean 注册表只是选择已创建对象，不应为了名称叫 Factory 就宣称实现了 GoF 工厂方法或抽象工厂。

## 结构型（7）

| 模式 | 适用证据 | 不适用或代价 |
| --- | --- | --- |
| 适配器 Adapter | 第三方或遗留接口与内部契约不匹配 | 单位、金额、错误和超时映射必须可验证；不能只改方法名 |
| 桥接 Bridge | 两个维度独立扩展，如通知类型与传输平台 | 只有一个变化维度可用策略或适配器 |
| 组合 Composite | 单个对象和树形对象组要统一处理 | 防循环、定义遍历及汇总语义；不是所有列表都需要树 |
| 装饰器 Decorator | 多个可选行为能以相同契约组合，如压缩和编码 | 顺序会改变结果；复杂状态组合可能更难调试 |
| 门面 Facade | 调用方被迫协调多个子系统，存在稳定高层用例 | 避免吸收所有职责形成新的巨型服务；不要隐藏事务边界 |
| 享元 Flyweight | 大量重复且不可变的内部数据确实占用显著内存 | 需测量；外部状态必须分离，缓存可能抵消收益 |
| 代理 Proxy | 必须控制对象访问，如远程、延迟加载、缓存或鉴权 | 避免与现有框架切面叠加；定义缓存失效和异常传播 |

代理偏访问控制，装饰器偏功能组合，适配器偏契约转换。通过需求区分，不按类结构猜名称。

## 行为型（11）

| 模式 | 适用证据 | 不适用或代价 |
| --- | --- | --- |
| 责任链 Chain of Responsibility | 节点可独立组合、按序处理或终止请求 | 固定两步可直接调用；显式区分“首个接收者处理”和“每步都执行”的管线 |
| 命令 Command | 操作需成为可传递对象，支持排队、审计或调度 | 不自动获得幂等/可撤销性；支付等副作用不能随意重放 |
| 解释器 Interpreter | 存在稳定小型规则语法、需解析为表达式 | 一般表达式优先成熟解析器；勿直接 eval 用户内容 |
| 迭代器 Iterator | 遍历方式需要与集合结构分离 | 语言已有迭代器时直接用；定义分页和修改时的一致性 |
| 中介者 Mediator | 多个协作对象彼此调用导致网状依赖 | 中介可能变成巨型对象，应按用例拆分 |
| 备忘录 Memento | 要保存局部对象快照并可恢复 | 大对象复制成本、敏感信息；不替代数据库事务或审计日志 |
| 观察者 Observer | 一个事件需通知多个可独立增加的订阅者 | 同步/异步、顺序、异常、取消订阅不同；不自动拥有可靠投递 |
| 状态 State | 同一操作随生命周期阶段改变且有明确合法流转 | 区分每状态对象与状态机转换表；简单枚举分支可能足够 |
| 策略 Strategy | 同一操作存在独立可替换的规则族，由调用方选择 | 稳定小分支无需额外类；注册策略不应改变未知类型行为 |
| 模板方法 Template Method | 算法步骤顺序稳定，少数步骤需由子类变化 | 只有默认方法与重写不构成算法骨架；变化多时优先组合 |
| 访问者 Visitor | 对稳定对象结构需频繁增加新操作 | 新增节点类型会影响所有访问者；简单遍历/模式匹配更直接 |

State 是 GoF 模式；State Machine 是一种建模与实现方式，并非额外的第 24 个 GoF 模式。

## 领域和架构候选（不计入 GoF 23 种）

- **Specification 规格**：业务谓词需要 and/or/not 组合；定义空值、短路与错误解释，不为一条简单校验建 DSL。
- **Repository 仓储 / Ports and Adapters 端口适配器**：领域规则与存储/供应商耦合；避免复制 ORM 已提供的机械 CRUD。
- **Domain Event / Outbox**：提交成功后需要可靠发送业务事件；事件表、重试、幂等和消费语义须明确，不等于 Observer。
- **CQRS**：读写模型存在实际不同的扩展或一致性需求；普通 CRUD 不应被迫拆分。
- **Saga / 补偿**：跨边界长事务确实需要业务补偿；补偿不是数据库回滚，可能再次失败。

## 输出选择

对选中的候选写：实际证据 → 需要稳定的契约 → 变化维度 → 最简单替代方案 → 模式成本 → 兼容性验证。
若收益小于成本，保持直接实现并说明理由。无需枚举所有模式。
