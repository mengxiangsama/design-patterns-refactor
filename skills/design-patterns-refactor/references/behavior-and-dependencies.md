# 行为基线与依赖隔离

用于需要修改的既有代码。已有足够回归覆盖时复用它；不要为无关模块补测试，也不要仅为可测试性新建多层接口。

## 先记录实际行为

- 从真实入口选择受影响的正常、边界和失败场景，记录输出、状态变化及对外副作用。先运行旧实现，区分观察事实和业务期望。
- 现有行为测试用于发现意外变化，不证明原实现正确。发现缺陷时单独记录；已授权修复的错误应测试正确目标，不能为保持旧测试通过而保留错误。
- 断言外部可观察的结果，不照抄私有分支或固定类结构。只有顺序、次数属于业务契约时，才断言协作者调用。
- 大型输出可用快照；只归一化不属于契约的时间戳等波动字段，别过滤金额、排序或错误信息来掩盖差异。
- 测试覆盖同一行为即可，不因重构结束自动删除基线测试；仅在确有等效覆盖或不再保护有效契约时精简。

## 选择最小替换入口

先判断是“依赖让代码无法运行”，还是“副作用无法观察”。优先复用构造注入、参数、现有客户端或 Mapper；确实写死依赖时，先做机械的小改动，再建立行为基线，勿同时重新设计业务。

| 依赖 | 适合的隔离方式 | 模拟不能证明的内容 |
| --- | --- | --- |
| 网络 | 替换现有客户端，模拟成功、业务拒绝、超时和无效响应 | SDK 序列化、验签、实际可达性；用适配器契约测试或沙箱联调补足 |
| 时间 | 注入时钟或明确传入当前时间；生产默认沿用原时区和精度 | 数据库时间、跨节点偏差；涉及这些时另验 |
| 数据库 | 通过现有 Mapper/Repository 控制查询结果，记录待写数据 | SQL、唯一约束、隔离级别、提交可见性和锁；需要真实数据库集成测试 |
| 随机、文件、全局上下文 | 注入已有随机源、临时目录或框架支持的请求上下文 | 生产权限、并发和真实分布；依任务风险补验 |

例如订单过期测试可提供截止前、截止时、截止后的时间，避免实际等待；保持原先“等于截止时间”的判定。已有 Feign/Mapper 通常可直接替换，不必再包一层同形接口。

## 验证可信度

模拟提交函数被调用，不等于另一连接已读到提交结果。涉及事务、跨服务可见性或并发更新时，应验证最终持久化状态，必要时使用独立连接或并发集成测试。不能执行就明确未覆盖，勿把单元测试写成线上验证。
