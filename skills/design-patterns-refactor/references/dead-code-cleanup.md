# 无用代码检查与清理

## 范围与证据

先确认用户要求只读检查还是实际清理，以及目标模块。选择项目已有的编译器、linter、静态分析工具和引用搜索，不为检查擅自安装服务或升级依赖。诊断是候选线索，不是删除授权或安全证明。

分类检查：

- 未使用的 import、局部变量、私有符号；无引用的类、配置和依赖需要额外核查入口。
- 仍在使用的方法中，定义后未读取的变量、读取前已被覆盖的赋值（dead store）、结果未使用的计算。
- 可证明不可达的分支、恒真/恒假条件、重复判断及无意义的中间转换。
- 重复实现属于重构候选，不直接等同于无用代码；公共签名中的未使用参数也可能是兼容契约。

追踪所有相关分支、循环、异常路径、闭包捕获及共享状态读写。说明具体哪次赋值无效，不因变量最终有用途而漏掉早期无效赋值，也不因一个路径未使用就认定全部路径无用。

仓库内搜不到调用时，继续核查框架入口、反射、注解、路由、依赖注入、序列化、模板、SQL/XML 映射、插件注册、脚本和外部消费者。Java/Spring 中特别注意 Controller、Bean、Mapper、定时任务；Python 的导入可能执行初始化，Go 的空白导入可能注册驱动，PHP 的动态调用和自动加载也可能是入口。测试覆盖不到不证明不可达。生成代码应检查生成来源，不直接清理生成产物。

## 删除前的副作用保护

区分“绑定或结果无用”和“整个表达式无用”。例如：

```java
boolean result = couponService.receive(memberId);
// result 确认未读取时，可以考虑只移除绑定：
couponService.receive(memberId);
```

不能删除发券调用。即使表达式看起来是 getter、构造、转换或纯计算，也要核查异常、空值检查、懒加载、初始化及资源行为；不能仅凭名称假定纯函数。

保护数据库/缓存写入、日志/审计/指标、校验与抛异常、锁、事务、资源关闭、defer/finally、异步等待与取消，以及调用次数、求值顺序和短路行为。消除重复调用前，证明调用无副作用且两次之间结果稳定；时间、随机数、远程读取和并发可变状态不能按普通常量处理。

被覆盖的赋值只有在右侧求值也可安全省略时才能整句删除；否则保留必要求值并遵循语言合法语法。简化转换或条件还需保持数值精度、溢出、类型转换、相等性及异常语义。对外接口、配置键、持久化字段和兼容分支若无法排除外部用途，只报告待确认。

## 实施与验证

将结果分成“有证据可清理”和“疑似、待确认”；没有证据的性能收益不作承诺。不为减少行数牺牲可读性，也不要求为简单清理引入模式。

实施时只修改授权范围内已证实的候选，小批量处理；保留用户现有修改。先保护受影响行为，按实际风险选择编译、类型检查、lint 和回归测试。方法内清理重点验证返回值、异常、边界输入，以及副作用的调用次数和顺序；涉及框架入口时补充相应加载或集成检查。验证受阻时不要将高风险疑似项升级为可安全删除。

报告逐项给出文件与行号、冗余类型、数据流/入口证据、拟删除与保留的行为、风险以及实际验证结果。只读分析不声称已删除；静态检查或编译通过不等于运行行为已完全验证；无法证明的项明确保留。
